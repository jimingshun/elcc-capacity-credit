# requirements目录

## 目录用途
管理核心、开发、报告和UI依赖分组及可复现锁。

## 包含什么
`base.in`、`dev.in`、`report.in`、`ui.in`和[locks](locks/README.md)。

## 不应放什么
本地虚拟环境、下载缓存、未经解析的临时依赖列表或密钥。

## 主要输入
`pyproject.toml`和已批准的直接依赖范围。

## 主要输出
Windows/Python 3.12锁文件。

## 关键入口文件或命令
依赖生成与安装命令以实施计划和锁文件头部说明为准。

## 与其他目录的关系
根`pyproject.toml`是包元数据入口，T26封装复用受控锁。

## 修改后影响哪些测试
运行`pip check`、包烟雾和受影响能力；依赖变化可能触发更大验证。

## Git提交规则
输入分组和锁文件同步提交，不提交`.venv/`。

## 保留、归档和清理规则
旧锁只在有明确兼容用途时保留，否则通过版本历史追溯。
